# Android API 契约核验

上下文没有给出 `requirement_dir` 和规格位置时，先读取当前需求自己的配置，并使用 `android-implement-and-verify` 的目录定位与旧规格兼容规则恢复上下文；不得猜路径或创建第二份规格。

以 `<requirement_dir>/api/api.md` 和它记录的原始来源为契约事实，读取实际网络层、DTO、mapper、Repository 和相关测试。不得仅凭 Kotlin/Java 类型反向推断服务端契约。

## 核验内容

- method、path、headers、query/body 参数、必传性和时间单位；
- 请求与响应字段名、类型、可空性、默认值、枚举和嵌套结构；
- 分页、空数据、错误码、HTTP 非成功、超时和解析失败；
- DTO 到领域模型的映射、缓存兼容和新增/删除字段影响；
- Mock/Fake 与正式网络实现是否隔离；
- 契约测试是否基于独立样例，而不是复述实现常量。

来源不可读或相互冲突时，区分已证明事实、客户端采用决定和未知项。未知项会改变序列化或业务行为时不得标记通过，也不得猜类型。

## 输出

固定输出四项：结论、实际核验范围、P0-P3 发现、未验证项与剩余风险。每条发现给出契约来源、代码位置、运行时影响和修复方向；实际范围说明已核验的 operation 和测试。

没有正式契约但用户确认使用临时契约时，可以给出“临时契约范围内通过”，不能冒充正式服务端契约通过。本 Skill 默认只核验；用户要求修复后再修改代码。
