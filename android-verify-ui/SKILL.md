# Android UI 验收

上下文没有给出 `requirement_dir` 和规格位置时，先读取当前需求自己的配置，并使用 `android-implement-and-verify` 的目录定位与旧规格兼容规则恢复上下文；不得猜路径或创建第二份规格。

读取项目规则、已确认规格、设计来源和当前 UI diff。先确认设计对应的页面、状态、设备尺寸及动态区域；无法访问 Figma 时使用用户提供的截图或导出，并明确资料边界。

## 验收步骤

1. 确认应用可启动、目标页面可稳定到达，设备或模拟器未被其他应用抢占。
2. 采集当前实现截图，与设计稿在相同页面状态下比较。
3. 检查布局层级、尺寸、间距、字体、颜色、图标、裁剪、系统栏和键盘遮挡。
4. 检查加载、空、错误、禁用、选中和长内容等规格要求的状态。
5. 检查点击反馈、焦点、触控区域、`contentDescription`、对比度和字号放大。

动态内容不要求像素逐点相等，应比较固定结构和允许变化区域。Figma 生成 XML 成功、APK 构建成功或页面能打开，都不能单独支持视觉通过。

## 输出

固定输出四项：结论、实际验收范围、视觉或交互发现、未验证项与剩余风险。验收范围记录设备、页面状态、设计链接或基准截图、实现截图；发现记录差异及严重级别。没有可比基准、目标状态无法到达或未采集截图时标记未验证；无 UI 变化时说明不适用依据。

本 Skill 只验收和报告。发现产品行为未知时返回主 Skill；用户要求修复后由实现流程修改代码并重新验收。
