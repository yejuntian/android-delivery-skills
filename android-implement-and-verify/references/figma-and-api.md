# Figma 与 API 输入

输入可以来自链接、截图、导出文件、文档或聊天。先读取实际可访问内容；读取失败时说明缺口，并只询问会改变实现或验收的处置决定。不得要求用户提供 Token、Cookie、密码或公司凭据。

## Figma

- 把用户提供的 Figma 链接原样记录到 `spec.md`，说明对应页面或状态。
- 先从项目确认页面使用 XML View、Compose 还是混合技术栈。
- 已确认规格中的 XML View 页面使用同级 `../figma-android-xml` 生成 XML 和资源；确认前只读取和核对资料。会话 Skill 列表未暴露该名称时，先检查该目录及其 `SKILL.md`，路径真实缺失后才能报告能力不可用。
- `figma-android-xml` 不负责 Kotlin/Java 业务接入、测试或最终视觉验收。
- Compose 页面不调用 XML Skill。设计资料不可读时，可以在用户确认后使用截图、导出或临时 UI 降级，但不得声明像素级还原通过。
- Android 资源名必须满足 Android 规则；设计工具给出的非法字符需要做最小合法化，并保留来源映射。

设计变化只影响颜色、尺寸、字体或资源时按实现细节增量处理；新增页面状态、交互或业务语义时把规格改回 `draft`。

## API

用户为当前需求提供 API 链接、截图、文件或聊天契约，即视为要求把该接口纳入需求。必须读取资料，并创建或增量更新唯一 `<requirement_dir>/api/api.md`；已有文件只合并当前接口，不覆盖其他接口。

读取 YApi、Swagger 或其他交互式接口页面时，先展开请求与响应 Schema 中所有可展开节点，再记录字段或判定资料缺失；嵌套对象、数组及其子项必须递归展开到页面不再出现未展开节点。点击无效时先定位实际展开控件并复核页面状态，不得把仍折叠的结构写成“接口未提供”或转问用户补充。

`api.md` 使用以下稳定章节，并在标题后维护可点击目录；章节锚点依次使用 `api-sources`、`api-contracts`、`api-errors`、`api-decisions`：

1. `来源与读取时间`：原始链接、文件、截图或聊天定位；
2. `接口契约`：按 operation 记录 method、path、请求和响应；
3. `错误与分页`：HTTP、业务错误、空数据和分页规则；
4. `冲突、采用决定与未知项`：区分已证明事实、客户端决定和待确认内容。

`api/api.md` 至少记录：

- 来源和读取时间；
- method、path、请求参数及是否必传；
- 响应字段、类型、可空性和示例；
- 错误与分页规则；
- 来源冲突、客户端采用决定和仍未知内容。

网页、截图和聊天不是低一等的输入，但只能记录它们实际证明的事实。来源冲突且会改变 DTO、序列化、业务行为或验收时询问用户；不得自行选择“看起来合理”的类型。

正式契约缺失但业务可独立开发时，经用户确认可使用 Fake 或临时契约。临时 DTO、错误码和枚举不得冒充正式服务端契约；正式资料到达后只更新受影响层和测试，只有业务语义变化才重新确认规格。
