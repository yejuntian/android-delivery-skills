## 阶段 2：提取 Android 资源和组件映射 (输出检查点 1)

在编写代码之前，必须输出一份包含以下部分的简明实现报告（设计规范报告），**建议直接按 `templates/figma-spec-report.md` 模板格式输出**：

1. **目标屏幕**
   - Frame 名称和大小
   - **【强制换算，禁止跳过】换算公式：**
     ```
     BASE_WIDTH = 读取 .env 文件中的 ANDROID_BASE_WIDTH 值
     scale      = BASE_WIDTH ÷ Figma画板宽度(px)
     dp值       = Figma标注值(px) × scale （若无法整除，强制保留小数点后两位，例如 12.33dp）
     ```
     > 📌 **配置项说明**：`ANDROID_BASE_WIDTH` 定义在 `.env` 文件中（当前值见文件）。
     > **如需修改基准宽度，只改 `.env` 一处即可，规则文件不需要动。**

     **执行前必须完成以下两步，不得省略：**

     **第一步 — 读取配置：**
     使用文件读取工具打开技能根目录下的 `.env`，路径为：
     `<skill根目录>/.env`（即与 `SKILL.md` 同级的 `.env` 文件）。
     找到 `ANDROID_BASE_WIDTH` 的值。
     > ⚠️ 若 `.env` 不存在或无该变量，**兜底默认值为 480dp**，并在报告中注明"使用默认值"。

     **第二步 — 在报告中明文写出换算三行：**
     ```
     ANDROID_BASE_WIDTH = ___dp  （从 .env 读取）
     Figma 画板宽度     = ___px  （从设计稿获取）
     scale              = ___ ÷ ___ = ___
     示例：导航栏高度   ___px × ___ = ___dp
     ```
     > 🔴 红线：**严禁用任何惯性值（360dp、375dp 等）替代从 `.env` 读取的值**。大模型极易因行业惯性偷换基准值，导致所有尺寸系统性偏移。写出上述三行是唯一有效的防呆检查点。
   - Figma frame 是否包含状态栏 / 导航栏
   - 滚动行为

2. **资源 Tokens (Resource tokens)**
   - 颜色 → 十六进制字面量命名（如 `@color/color_FFFF86FC`，严禁语义命名）
   - 间距 → 高度、宽度、间距（本阶段仅盘点数值，阶段3必须100%硬编码内联，禁止提取名称）
   - 圆角半径 → 圆角半径数值（本阶段仅盘点数值，阶段3必须100%硬编码内联）
   - 排版 → 文本外观、大小、粗细、行高（本阶段仅盘点数值，阶段3必须100%硬编码内联）
   - 阴影 / 高度近似值

3. **布局结构**
   - 根布局选择
   - 主要部分
   - 可重用的项目布局 (item layouts)
   - RecyclerView / ScrollView / NestedScrollView 决策

4. **组件映射**
   - Figma Button/Input/Card/TopBar/ListItem/etc. → Android View 或自定义组件
   - 状态：默认、按下、禁用、选中、错误、加载中

5. **资产 (Assets)**
   - 要导出的图像
   - 要转换为 VectorDrawable 的图标
   - 图像缩放类型：`centerCrop`、`fitCenter`、`centerInside` 等

6. **风险 / 假设**
   - 缺失的字体
   - 未知的系统栏
   - 未知的响应式行为
   - 缺失的状态
   - 模糊的图像裁剪或阴影

只有在输出此报告之后，才能开始进入下一步的资源与代码实现。
