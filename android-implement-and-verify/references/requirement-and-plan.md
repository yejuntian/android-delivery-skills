# 需求、BDD 与实施计划

## 需求事实源

- 需求正文使用 `<requirement_dir>/docs/<需求名>.md`；docx 只作初始输入，首次 `init` 后转写为 md。
- 每个已接受答案立即合并进 `requirement_file`，替换失效表述并同步受影响 BDD、旧业务影响和测试预期。聊天不能替代事实源。
- `## 待确认` 必须存在；全部澄清后写 `- 无`。字段、文案、接口和数据来源不足时保留待确认，不脑补。
- 人维护需求、实施计划、业务和测试代码；脚本维护快照、修订、映射、收据、route、证据和最终结果。

## BDD 质量

- 每个 `### BDD-### 场景名称` 包含 Given/When/Then；独立触发、异常、恢复和边界拆成独立场景。
- 同一触发有多个验收结果时使用结构化 Then 列表，不用自由文本或 And 隐藏结果。
- 为可观察场景分配稳定 ID；未变化内容不得因排序改号，一个 BDD 可以映射多个真实测试。
- 确认前检查主流程、备选、异常、恢复和非功能约束；缺少时标记待确认或“不适用 + 原因”，不为凑数量脑补。
- 只问会改变实现、验收或测试范围的问题。存在依赖时一次只问当前最高优先级问题；关键业务含义不清时继续阻塞。

## 已上线业务影响

需求理解最前面展示：

1. **本次明确修改**：需求允许改变的已有行为，写清修改前后。
2. **必须保持不变**：可能受影响但没有授权改变的已有行为，必须有代码、测试、契约或用户事实依据。
3. **暂时无法确认**：是否允许改变仍不明确，作为冲突阻断确认。
4. **明确不修改范围**：不会触及的相邻业务和公共边界。

最终 diff 发现未登记的已有业务调用方或可观察变化时，立即写回需求并进入增量闭环，不能只在报告补一句风险。

## 澄清方式

- 先说明模糊点、原因和已知事实；代码能证明技术事实时直接采用，但不能仅从现有表现推导产品规则。
- 能形成真实互斥方案时提供 2～4 个候选，说明可观察行为和直接影响，并允许用户自定义；金额、权限、隐私和线上行为不得自动代选。
- 用户回答后复述合并后的最终语义；仍冲突时只澄清当前冲突，不静默取舍。
- 用户回复同时包含“确认”和新变化时仍按变化处理，写回并重新 `init` 后等待纯确认。

## 修订清单

- `requirement-revision.json` 使用 `ADDED/CHANGED/REMOVED/UNCHANGED/SUPERSEDED` 和 `CONFIRMED/PENDING/REJECTED/CONFLICT`。
- 普通新增、修改和未变化由 `init/check-env` 物化；删除、改号和替代必须使用显式 `--revision-file` 说明处置。
- `confirm-requirement-update` 只推进当前需求修订，不改变最初 Git 基线；重复 `check-env` 安全复用当前起点。
- 新的串行需求必须完成或取消当前需求，再按 `parallel-and-resume.md` 轮换并使用 `check-env --new-requirement`。

## 聊天事实收件箱

对可能改变行为但尚未形成完整需求的补充，先写 `.state/fact-inbox.json`。`PENDING` 和 `DISCUSSION` 不能开发；即使状态为 `CONFIRMED`，仍需补齐范围和验收结果、写回需求并执行 `confirm-requirement-update`。最终 gate 复核收件箱，防止聊天确认绕过正式修订。

## 实施计划和影响半径

需求确认后生成唯一 `docs/实施计划.md` 和 `test-cases/impact-radius.json`。计划必须展示：

- 实现范围。
- 已上线业务影响。
- 预计修改文件。
- 测试方案。
- 影响半径摘要。
- 明确不修改范围。

影响半径覆盖当前需求基线以来所有已确认语义变化；`allowed_files` 使用精确文件，`allowed_dirs` 使用以 `/` 结尾的目录前缀，不用通配符。计划中的 BDD、预期文件和测试必须与影响半径交叉对应。

用户确认展示内容后执行 `confirm-plan`。收据绑定需求修订、需求摘要、计划摘要和影响半径摘要；任一变化都会使旧收据失效。没有改变这六类边界或影响半径的实现细节完善不重复确认。

## 人读产物

所有人工 Markdown 放在 `<requirement_dir>/docs/`。脚本从机器产物渲染续接指南、需求修订说明、测试映射说明、需求测试追溯和交付结论；这些视图不成为第二事实源。审查、决策、问题、设计和配置说明按需使用 templates，不创建空目录或保存凭据。
